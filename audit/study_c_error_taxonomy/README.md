# Study C - Native-Speaker Error Taxonomy

## Status: Pilot (single model, ungenerated annotation)

## What exists in this directory right now

- `annotation_guidelines.md` - the 9-code error taxonomy (E1-E9) and
  annotation procedure.
- `llm_outputs_pilot.csv` - **10 real Bangla outputs, all generated by
  a single model (Claude, Sonnet 5)**, across 5 tasks (summarization,
  open QA, formal letter, dialect rewrite, creative writing), 2 samples
  per task.
- `annotations_template.csv` - blank template; each annotator copies
  this to `annotations_r1.csv`, `annotations_r2.csv`,
  `annotations_r3.csv` and fills in 0/1 per error code per output.
- `annotator_demographics_template.csv` - blank demographic form
  (region, dialect exposure, education) required for the paper's bias
  reporting.
- `compute_agreement.py` - computes per-code and pooled Fleiss' kappa
  once at least 2 filled annotator files exist; verified against
  synthetic random data (produces near-zero kappa on random 0/1
  ratings, confirming the implementation is correct).

## What is honestly NOT done yet

1. **No human annotation has happened.** The kappa values and error
   findings described in the blueprint (`LRL-LLM-MASTER-PROTOTYPE.md`
   → D3) do not exist yet — they require 3 real Bangla-speaking
   annotators to independently fill in the template.
2. **Only one model's outputs are included.** The full design calls
   for 4 LLMs (Claude, Gemini, Llama-3, Qwen2). This pilot only has
   Claude outputs because API keys for the other three (Groq, Google
   AI Studio) were not available in this environment. Do not describe
   this pilot as multi-model in the manuscript.
3. **Sample size is 10, not ~200.** This is a structural pilot to
   validate the pipeline (taxonomy, template, kappa script), not the
   statistically powered study the paper needs.

## To complete the full study

1. Obtain free API keys (Groq, Google AI Studio) and generate outputs
   from Gemini Flash, Llama-3, and Qwen2 for the same or an expanded
   prompt set, honestly labeling each row's `model` column.
2. Expand to ~200 total samples across the 5 tasks.
3. Recruit 3 Bangla-speaking annotators (ideally different regions/
   dialect backgrounds) to independently annotate using
   `annotations_template.csv`.
4. Run `compute_agreement.py` to get real Fleiss' kappa per code and
   pooled; target ≥0.70 per the pre-registered protocol.
5. If automatic metric scores (BLEU/chrF/COMET/LLM-judge) are computed
   separately for the same outputs, correlate them against
   `error_counts_per_output.csv` using Spearman's rho (see the
   blueprint's Study C design for the exact analysis).
